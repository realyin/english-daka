# 排障记录

线上（家里平板）发现、但在开发机上不容易复现的问题。每条记：**症状 → 走过的弯路
→ 怎么量准 → 根因 → 修复 → 验证数字**。弯路要留着，下次少走一遍。

## 2026-08-30 · 封面流「抖动」，其实是整个页面在横向滚

### 症状

用户录了一段 3.5 秒的视频（手机拍平板屏幕）：在目录页用手指拨封面流时，画面
来回哆嗦。肉眼看像是那一行卡片在抖。

### 弯路一：没减相机运动，读出来的数是假的

第一版测量：逐帧抽出「字母行」那条横带，跟**前一帧**做互相关，累加位移。
读出 ±30px 的大幅摆动。

**这个数是错的，两处都错：**

1. **相机本身在动。** 手持拍摄，整个画面都在飘。必须拿一条**页面内容不会影响
   的参照带**（浏览器地址栏）同帧测一次，两者相减才是页面真实位移。
2. **卡片是重复图案**（等宽的彩色方块），互相关的峰会锁到隔壁那张卡上去。视频
   又糊，峰更平。表现就是相邻帧读出 ±30 的跳变、中间夹着一串 0 —— 一看就是
   锁错峰，不是真运动。

减掉参照系之后，字母行的真实位移只有 ±1px。

### 弯路二：测量带里混进了被怀疑的元素

第二版：拿地址栏当参照系，量「词族行」。这次读出干净的双稳态方波（在 +3.0 和
−3.8 两个值之间来回跳，2.3 秒里没有任何中间值，约 10Hz）。

于是断定：手指按住不动时触摸屏上报的接触点质心在两个估计值之间跳，被
`STEP()` 的 2 倍增益放大成卡片哆嗦。据此加了死区 + 低通（见下「顺带改了什么」）。

**结论是错的。** 因为那条测量带（`y 300–420`）里既有卡片也有页面背景，量到的
其实是**页面在动**，我当成了卡片在动。

用户提出「感觉像是左右滑动改动了页面大小，页面放不下才动的」，才回去重量。

### 量准了：动的是整个页面

先把坐标读准（把某一帧放大 3 倍、画上 y 标尺再看），得到：

| 区域 | 帧内 y | 备注 |
|---|---|---|
| 浏览器地址栏 | 40–66 | 参照系 |
| 页面标题区 | 74–128 | 标题 + 副标题 + 绿色按钮，**一张卡都没有** |
| 卡片上沿 | 140 起 | |

还有一点：**帧左侧 x < 70 是屏幕外的桌面**，跟着相机动，不能算进测量带。

拿「页面标题区」（纯静态、无卡片）对「地址栏」：

```
帧    水平位移     竖直位移
20     +3.81       +1.70
22     -3.96      -11.20     ← 竖直方向另有一次整页滚动
69     +2.86       +1.68
73     -3.79       +0.08
83     +2.90       +1.86
88     -3.72       -0.15
```

标题、副标题、分组标题全在跟着动 ⇒ **动的是整个页面，不是那一行卡片。**
水平摆幅 6.65 帧像素 ÷（卡宽 86 帧像素 / 268 CSS px）≈ **17–21 CSS px**。

### 根因

```css
.stage{ width:100vw; margin-left:calc(50% - 50vw); }   /* 没有 overflow 裁剪 */
.cover{ position:absolute; left:50%; ... }              /* 折到最外侧 translateX(±160%) */
```

折叠到最外侧的卡片被 `translateX` 甩出 `.stage`，而 `.stage` 是 `overflow:visible`
—— **绝对定位的溢出内容会算进文档的可滚动区域**，页面因此横向可滚。手指在封面流
上横划，浏览器就顺手把整页一起平移。

实测各视口宽度下页面能横滚多远（`scrollLeft=99999` 再读回来）：

| 视口宽 | 可横滚 |
|---|---|
| 360 | **253 px** |
| 414 | **290 px** |
| 480 | 263 px |
| 600 | 203 px |
| 768 | 119 px |
| 834 | 86 px |
| 1000+ | 7.5 px |

窄屏最严重，因为 `--cw:clamp(212px, 64vw, 268px)` 在窄屏取 `64vw`，卡片相对视口
更大，`translateX` 甩得更远。1000px 以上只剩 7.5px，那是另一个来源：**`100vw`
包含滚动条宽度**，比内容区宽出一条滚动条，`.stage` 左边缘因此落在 `-7.5px`。

### 为什么 `body{overflow-x:hidden}` 挡不住

代码里**早就写了** `body{overflow-x:hidden}`，但实测页面照样能滚 290px。

原因：body 的 `overflow-x:hidden` 配 `overflow-y:visible`，按 CSS 规则另一轴会被
提升成 `auto`，**body 自己变成滚动容器，就不再往视口传递了**。视口的溢出行为取的
是 `html` 的值。

### 修复

`index.html` 加一行：

```css
html{ overflow-x:hidden; }
```

（body 上那行保留，无害。）

考虑过但没用的两个方案：

- `.stage{ overflow:hidden }` —— 只能降到 7.5px（挡住了卡片溢出，挡不住 `100vw`
  比内容区宽的那截），而且会裁掉卡片阴影（stage 高度只比卡片多 34px，上下各留
  17px，阴影 `0 8px 22px` 要 30px）。
- `overflow-x: clip` —— 语义最合适（裁剪但不产生滚动容器），但要 Chrome 90+ /
  Safari 16+，这个项目的浏览器底线到 iOS 11，用不了。

### 验证

修复后各宽度可横滚**全部为 0**：

| 视口 | 360 | 414 | 768 | 834 | 1280 |
|---|---|---|---|---|---|
| 修复前 | 253 | 290 | 119 | 86 | 7.5 |
| 修复后 | **0** | **0** | **0** | **0** | **0** |

竖向滚动完好（2270–2575px），29 张封面照常渲染，侧卡和阴影都没被裁掉，拖动/翻页
功能正常。

> 平板上没能复现出抖动了，但这是「没复现」不是「证明修好了」—— 真正的证据是
> 可横滚从 290px 变成 0，浏览器已经没有横向平移页面的余地了。

### 顺带改了什么（**不是**这个 bug 的解）

在走弯路二的时候给拖动加了两样东西，留下了，但要说清楚**它们没有修好视频里的问题**：

- **死区 `DEAD=10`**：`|dx|` 没过 10px 之前 `pos` 一帧都不画。原来那个 `>10px`
  的阈值只用来区分点按/拖动，**完全没挡住画面** —— 手指一落下 `pos` 就开始 1:1
  跟着 `clientX` 走。
- **一阶低通 `LOWPASS=0.35`**：`pos = p` 改成 `pos += (p - pos) * 0.35`。
- **`pointerId` 校验**：原来 `pointermove` 不认指针，第二根手指（握平板的虎口）
  按下会把 `startX` 抢走，两个指针交替刷新 `pos` 会跳一整张卡。这是真隐患。

前两条针对的是「原始输入未经滤波 + `STEP()` 的 2 倍增益」，本身站得住（合成
±8px 抖动输入，改前卡片摆 21.6px、改后 0），但视频里的问题不是它。

## 2026-08-30 · 点最外侧那张卡，直接跳到最后一课

### 症状

目录页某组中间是 `Letter I`，点最右边那张 `B`（离中心第 2 张）旁边，画面直接跳到
了这一组的最后一课。

### 根因（两层，第二层是修第一层才暴露出来的）

**第一层：收起来的卡只是透明，照样能点。**

`placeCover()` 里离中心超过 2.6 张的卡「收起来」：

```js
if(a > 2.6){
  el.style.opacity = 0;                                  // 只是看不见
  el.style.transform = `translateX(${sign*160}%) scale(.5)`;
  el.style.zIndex = 0;
  // 缺 pointer-events:none
```

`opacity:0` 不影响命中测试，而且**所有收起来的卡都叠在 `translateX(±160%)` 同一个
点上**，那正好是最外侧那张折叠卡画着的位置。点上去命中的是 DOM 里最后那张（= 最后
一课），`release()` 走 `go(i)` 就跳到最后。

**第二层：`.rack` 挡在所有折叠卡前面。**

加了 `pointer-events:none` 之后幻影区间消失，但最外侧那张卡变成**完全点不到**。
因为 `.rack` 是 `transform-style:preserve-3d`，**3D 上下文里排序看的是深度，不是
z-index**。折叠卡都被 `translateZ(-88px)` 推远了，而 `.rack` 自己在 z=0 平面且
`inset:0` 铺满整个 stage，于是挡在它们前面。

也就是说：**「点侧卡转到中间」这个功能一直是坏的**，之前只是碰巧被收起来的卡
（z=0，压在 rack 前面）接住了点击，才显得「有反应」——只不过反应是错的。

用 `elementFromPoint` 沿 stage 中线扫一遍就一目了然（视口 1000px，中间是 #0）：

```
修复前                          修复后
0-350   : rack                  0-355  : stage
360-620 : #0 S                  360-625: #0 S      ← 画在 359-627
630-740 : rack                  630-785: #1 T      ← 画在 603-787,原来只有 30px 能点
750-780 : #1 T   ← 只剩 30px    790-795: stage
790-980 : rack   ← #2 M 整片点不到  800-950: #2 M   ← 画在 800-953,原来完全点不到
860-980 : #10 D  ← 幻影,最后一课
```

### 修复

```css
.rack{ …; pointer-events:none; }     /* rack 自己不接点击 */
.cover{ …; pointer-events:auto; }    /* 卡片自己收回来 */
```
```js
// placeCover 收起分支
el.style.pointerEvents = "none";
// 非收起分支
el.style.pointerEvents = "auto";
```

### 验证

414 / 768 / 1000 / 1280 四个宽度下：

- 各卡**可点区间与画出来的区间一致**（误差 ≤ 5px，就是扫描步长）
- 卡与卡之间的空隙、两侧空白 → 命中 `.stage`，只拖动、不选卡
- 全部 7 组扫一遍：`opacity < 0.05` 却仍可点的卡 **0 张**
- 点中间那张仍然进课程（实测跳到 `app.html?lesson=k2-letter-s`）
- 死区、拖动、翻页不受影响

### 教训

**`opacity:0` 不等于不可点。** 想让元素退出交互，要 `pointer-events:none` 或
`visibility:hidden`。

**`preserve-3d` 里 `z-index` 基本不管用**，排序看的是 translateZ 深度。想靠
z-index 把某层压下去，在 3D 上下文里会失效——这次 rack 的 z-index 是默认值（auto，
等价于同层），却压过了 zIndex 80 的卡片。

**验证交互层级不要靠"看着对"**，用 `elementFromPoint` 沿一条线扫出命中区间，跟
`getBoundingClientRect()` 画出来的区间对照，错位一眼就现形（脚本见下「扫出可点
区间」）。

## 可复用的方法

### 从「拍屏视频」里量位移

```python
# 1) 抽全帧
#    ffmpeg -i x.mp4 ff/%03d.png
# 2) 关键三条:
#    a. 必须减参照系 —— 拿浏览器工具栏（页面内容影响不到它）同帧测一次再相减,
#       否则量到的是相机在抖
#    b. 测量带必须避开被怀疑的元素 —— 想证明"不是卡片在动",带子里就一张卡都不能有
#    c. 重复图案（等宽卡片、标签栏）会让互相关锁错峰,把位移限幅在 ±12px 以内,
#       并且用梯度剖面而不是灰度剖面（对亮度漂移鲁棒）
import numpy as np
from PIL import Image

def prof(g, y0, y1, x0, x1, axis=0):
    p = g[y0:y1, x0:x1].mean(axis=axis)
    p = np.gradient(p)              # 取边缘,抗亮度漂移
    return p - p.mean()

def shift(p, q, m=12):              # 限幅 ±m,防止锁到隔壁的重复图案
    n = len(p); cs = {}
    for s in range(-m, m+1):
        a, b = (p[s:], q[:n-s]) if s >= 0 else (p[:n+s], q[-s:])
        d = np.linalg.norm(a) * np.linalg.norm(b)
        cs[s] = float((a*b).sum()) / (d or 1)
    bs = max(cs, key=cs.get)
    if -m < bs < m:                 # 抛物线插值到亚像素
        y0, y1, y2 = cs[bs-1], cs[bs], cs[bs+1]
        den = y0 - 2*y1 + y2
        if den: bs = bs - 0.5*(y2-y0)/den
    return bs

# 每帧: shift(参照带) 和 shift(目标带) 相减 = 页面真实位移
```

**读坐标别靠估**：把某一帧放大 3 倍、用 `ImageDraw` 画上 y 标尺再看，一眼就能读出
每个区域的边界，也能看出屏幕外的桌面占了哪几列。

**双稳态方波 = 有东西在两个离散状态之间翻**，不是手在抖（手抖是连续的）。但
「在哪一层翻」要靠测量带定位，别急着归因。

### 扫出「哪个位置实际点中了谁」

```js
const S = document.querySelectorAll('.stage')[0];
const C = [...S.querySelector('.rack').children];
const R = S.getBoundingClientRect(), cy = R.top + R.height / 2;
const runs = [];
for (let x = 0; x < innerWidth; x += 5) {
  const el = document.elementFromPoint(x, cy);
  const cov = el && el.closest ? el.closest('.cover') : null;
  const hit = cov ? '#' + C.indexOf(cov) : (el ? (el.className || el.tagName) : 'null');
  if (runs.length && runs.at(-1).hit === hit) runs.at(-1).x2 = x;
  else runs.push({ x1: x, x2: x, hit });
}
// 再拿每张卡的 getBoundingClientRect() 对照:命中区间 ≠ 画出来的区间 = 有东西挡着
```

改 CSS 前先在页面里试，不用改文件：

```js
const st = document.createElement('style'); document.head.appendChild(st);
st.textContent = '.rack{pointer-events:none;}';   // 量一遍
st.remove();                                       // 再量一遍对照
```

### Claude 的浏览器面板：rAF 不跑

面板隐藏时 `requestAnimationFrame` **一帧都不触发**（实测 500ms 内 0 帧）。所以
任何靠 rAF 的行为（这里是松手后的弹簧回弹、点侧卡转到中间）在里面**验不了**，
会表现成「功能没反应」。判断方法：拿改动前的备份文件跑同一个用例，如果结果一样，
那就是环境限制不是回归。`setTimeout` 是照常跑的。

另外 `navigate` 到同一个 URL 会吃缓存，改完文件量出来还是旧行为。加个查询串绕开：
`location.replace('/index.html?v=' + Date.now())`。这次就在这上面白折腾过一轮。
